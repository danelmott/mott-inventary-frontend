# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

A Next.js 16 frontend **boilerplate** (App Router, JavaScript, Tailwind v4) carrying the "Mott" design system: a Material Design 3 palette generated from one seed color, M3 typography, and ready-made components. It is copied as the base of a new project and its components are edited in place — it is not a package. Components receive only data and functions; their UI copy is written inside them (Spanish, "tú"), and forms own their own state.

## Commands

```bash
npm run dev      # next dev — the app at http://localhost:3000 (redirects to /app/home)
npm run build    # next build (catches SSR / server-client boundary errors)
npm run start    # serve the production build
npm run lint     # eslint (eslint-config-next core-web-vitals)
npm run theme    # regenerate the static color block in app/globals.css from the default seed
```

There is no test or typecheck script.

Setup: `cp .example.env .env`. Variables: `NEXT_PUBLIC_API_URL` (the Laravel backend), `NEXT_PUBLIC_ROOT_PATH` (route without session: logout and closing the email-link pages go there, `/` by default) and `NEXT_PUBLIC_REDIRECT_PATH` (where the user enters after login or confirming the email, `/app/home` by default) and `NEXT_PUBLIC_GOOGLE_AUTH_URL` (the backend route "Continuar con Google" opens, e.g. Socialite's `/auth/google/redirect`; the backend redirects back to the frontend), plus the four `NEXT_PUBLIC_REVERB_*` (key, host, port, scheme: the backend's `REVERB_*`) for the assistant chat. If Google is used, `GET /api/me` must include `has_password` (the backend's `UserResource` adds it).

## Structure (create-next-app layout, project code outside `app/`)

Two halves: `mott/` is the design system (imported as `@mott/*`), the root `components/`, `hooks/` and `lib/` are the project's own code (imported as `@/components/...` etc., each folder has a README with an example). Project code uses Mott; Mott never imports from the root folders. Where each new file goes (areas in `components/<área>/`, `shared/`, `layout/`; global providers in `contexts/`; API calls in `lib/api/<recurso>.js`) is the table in README → "Dónde crear cada cosa".


- `app/` — routes only: `layout.js` (server; imports `./globals.css`, loads DM Sans via `next/font/google` as `--font-dm-sans`, puts `THEME_SCRIPT` as an inline `<script>` in `<head>` so the saved palette and mode are on `<html>` before the first paint, wraps children in `providers.js`), `providers.js` (`'use client'`: `ThemeProvider`, `ToastProvider` and `AuthProvider`, all from `contexts/`), no root `page.js`: `next.config.mjs` redirects `/` to `/app/home` (307). `app/app/` is the app: `layout.js` (the Navbar — Inicio, Productos, Transacciones, Calendario — and the `main`, which never scrolls on desktop; its children go through `components/layout/AppGate.js`, which only renders the sections with a session, a verified email, a name and a commerce, and otherwise opens AuthModal / OnboardingModal / `CommerceModal`) and its sections `home/` (`/app/home`, the default `NEXT_PUBLIC_REDIRECT_PATH`), `products/`, `transactions/` and `calendar/`, each `page.js` rendering one component from `components/<área>/`.
- `mott/ui/` — Button, Icon, GoogleIcon, Avatar (blobatar from a name: same name → same avatar; string `expression`, `animate`), Input and Select (surface and padding from the `mott-field` utility; the Select panel logic — position, open/close animation, click outside — lives in `mott/services/useSelect.jsx`), Text, Loading (only the component: an `<svg>` with the `mott-loading` utility — CSS spin, 6s per turn, 12s with reduced motion — and an SVG `<animate>` on the path's `d` for the morph, so both run from the first paint, before hydration; the shape geometry, measured in plain JS without DOM, and the `<animate>` attributes (`morph`, `null` with reduced motion) live in `mott/services/useLoading.jsx`, no GSAP), DragScroll (only the component: the drag, the inertia and the edge fade live in `mott/services/useDragScroll.jsx`), SwatchGrid (the theme colors; picking one calls `setColorSeedHex`), ModeButtons (light/dark/system, reads and sets `mode` from `useTheme()`), PasswordField (Input with the show/hide button), ChipSelect (multiple choice chips like M3 filter chips: `value` is the array of picked values, `onChange(values)` gets the new array; the `mott-check-chip` utility, the picked one (`aria-pressed`) gets `primary-soft` and grows a check), ComposerField (long text: a bordered box (`mott-composer-field`) that shows up to `rows` lines and opens a `Modal` with `AnchoredAnimation` holding the borderless editor (`mott-composer-editor`); Enter or "Listo" close it keeping the text, Shift+Enter is a new line; `hint` and the `maxLength` counter sit under the box; its open state, focus and Enter live in `mott/services/useComposerField.jsx`), FormError (the error line under a form; renders nothing without text), Toast (UI only; its timer, enter/exit, drag-to-dismiss and the stack container live in `mott/services/useToastBehavior.jsx`).
- `mott/layout/Navbar.js` — items `{ icon, label?, ariaLabel?, href?, onClick?, active? }` rendered as `next/link` when they have `href`; active item comes from `usePathname()` unless `active` is given. `account` (boolean) adds the button that opens `OptionsModal`; `logo.account` makes the logo open it instead of navigating. `action` (`{ icon, label, onClick }`) puts another action in that button's place (e.g. an X that closes a modal). Its logic (active item, selection morph of rail and bar, logo/account shapes, scroll to the active item, opening the account menu) lives in `mott/services/useNavbar.jsx`.
- `mott/modals/` — `Modal` (base `<dialog>` → overlay + `mott-dialog-layer` → panel (`data-mott-panel`); its open/close, stacking, veil, scroll lock and `swipeToClose` logic lives in `mott/services/useModal.jsx`; stacking via `mott/hooks/useModalLayer.js`, veils via `mott/animations/scrim.js` — the top modal drives its veil and the one below in one tween so the page stays at 32%, see `mott/hooks/useModalLayer.md`), FullscreenModal (passes `swipeToClose` through), ThemeModal (uses `ModeButtons` and `SwatchGrid` from `mott/ui/`), OptionsModal (orchestrator only, takes `open`, `onClose`, `triggerRef`: rows are the `options` array in the component, mapped), SettingsModal, LogoutModal (does `POST /logout` itself, clears the user, goes to `NEXT_PUBLIC_ROOT_PATH`; `onLoggedOut` lets the opener close too — OptionsModal passes its `onClose`), OnboardingModal (the name step starts with the session's name from `useAuth()`, e.g. the one OAuth brings, each time it opens); `auth/AuthModal` is one modal with screens login/register/verify/recover/reset — login and register carry "Continuar con Google" (`handleGoogle` in `useAuthModal`: `window.location.assign(process.env.NEXT_PUBLIC_GOOGLE_AUTH_URL)`, a full navigation and not a fetch because Socialite keeps the OAuth state in the backend session); verify is link based ("Revisa tu correo", Laravel style: no buttons, polls `refreshUser()` (`GET /api/me`) and moves to the `verified` screen (green hero, "Continuar" does `router.replace(process.env.NEXT_PUBLIC_REDIRECT_PATH)` from `useAuthModal` without closing the modal; login with a confirmed email does the same from `useLoginScreen`) when `email_verified_at` is set; opening the link or a 204 on resend throws if the user can't be reloaded, resend with cooldown), recover sends the Laravel reset link (then "Revisa tu correo"), reset is the new-password form opened from that link (`app/password-reset/[token]/page.js`, a client page that opens AuthModal with the `token` prop), and the verification link lands on `app/email/verify/[id]/[hash]/page.js` (client page, `verification` prop `{ id, hash, expires, signature }`, sent once to `GET /email/verify/...`); both read their params with `use()` and go back to `NEXT_PUBLIC_ROOT_PATH` on close; it is one component that renders each screen conditionally, and its hook `useAuthModal` also drives the curtain swap between screens and the submit of the shown one.
- `mott/services/modals/` — the logic hooks of the big modals (`useSettingsModal.jsx` → `useSettingsModal` (everything of SettingsModal: session from `useAuth()`, sections ("Cambiar contraseña" only shows when `user.has_password` isn't `false`: Google accounts have no password), the two-step password change with its own `fetcher` calls to `POST /user/confirm-password` and `PUT /user/password`, Laravel errors and a `success` step (green hero, "Listo" goes back to the empty first step); the modal is one component rendering each screen conditionally), `useAuthModal.jsx` → `useAuthModal` (navigation only; one hook per screen in `auth/use*Screen.jsx`, each doing its own API calls with `fetcher`), `useOnboardingModal.jsx` → `useOnboardingModal`); OptionsModal has no hook: it only orchestrates its child modals. the modal component keeps only the UI and destructures what the hook returns.
- `mott/gestures/` — drag to close a modal, optional: `<Modal swipeToClose />` or `swipeToClose={{ pointer, distance, fling }}` (`swipeOptions` fills the defaults `'touch'`, `120`, `450` — the same fling as Toast); FullscreenModal passes it through; no Mott modal turns it on. `drag.js`: `createDrag(el, { axis: 'x'|'y'|'both', pointer, canStart, onStart, onMove, onEnd })`, its own drag engine (not GSAP `Draggable`, whose `touch-action` killed native scroll inside a panel): touch events for touch (`touchmove` non passive, follows the first finger by `identifier` and ignores the rest, claimed after 8px; with `x`/`y` the axis is locked, with `both` the first movement only picks which scroller to check), pointer events for mouse/pen; never starts on `[data-mott-gesture-ignore]`, form fields, selected text or a scroller that can still move that way; `pointer: 'touch'` (default) or `'any'`. `swipeToClose.js`: the drag moves the **layer** (`mott-dialog-layer`, between the veil and the panel in `Modal.js`), never the panel, so the normal close animation can measure and write the panel. `attachSwipeToClose` (layer goes where the finger goes with an elastic limit — `rubberband` toward `MAX_PULL` 96px — and grows from the panel's center: a quick 6% lift with `EXPRESSIVE.spatial.fast` when the drag is claimed (so it reads as picked up) plus up to 10% more with the distance — a panel that fills the viewport (FullscreenModal) shrinks instead, down to 90% like M3 predictive back (`SHRINK`), and the layer rounds to `--radius-xl` with `overflow: hidden`; with reduced motion it follows the finger without scaling; grabbing it mid spring-back continues from where it is (`fingerFor`, the inverse of `rubberband`), but only this finger's travel decides the close; `distance` is measured on the finger, `scrubScrim` lightens the veil; released past `distance` or with a `fling` → `ctx.close()`, else `settleSwipe`: spring back), `closeFromSwipe(ctx, close)` (clears the layer, builds `modalAnimation.close` so it measures clean, restores the layer and tweens it to rest in the same timeline with `MODAL_EASE`, so the panel lands on its trigger; without trigger the layer stays). `useModal` attaches it while open and idle (`busy()` of `useEnterExit`); the veil leaves like any close (`hideScrim`); if the parent doesn't close within 2 frames, or it reopens mid exit, `settleSwipe`.
- `contexts/authContext.jsx` — the project's `AuthProvider` (mounted in `app/providers.js`): only the global session user. `useAuth()` → `{ user, setUser, refreshUser, loading, setLoading, isAdmin }`, `user` from `GET /api/me` on mount. `refreshUser()` (`fetcher('/api/me')`) fetches the user, stores it and returns it (`null` when the response isn't ok, keeping the current user; network errors propagate). Login/register/verify/logout calls live in each modal's hook: AuthModal's screen hooks reload the user with `refreshUser()`, LogoutModal calls `setUser(null)`. Mott's auth hooks, SettingsModal and LogoutModal import `useAuth` from here.
- `contexts/CommerceContext.jsx` — `CommerceProvider` (inside `AuthProvider`): the commerces of the verified user (`GET /api/commerces`), the chosen one remembered in localStorage (`mott-commerce`). `useCommerce()` → `{ commerce, commerces, loading, error, selectCommerce, addCommerce, can }`; `can('view_profits')` etc. reads the commerce's `permissions`. Every section's data hangs from `commerce.id`.
- Backend (`mott-inventary`, Laravel): one file per resource in `lib/api/` (`request.js` → `request`/`requestAll`: JSON, Laravel's message as the thrown Error, all pages of a paginated list; `products`, `transactions`, `sales` (daily summaries and monthly metrics), `commerces`, `assistant`), each mapping the response to the shape the UI uses (decimal strings → numbers). Hooks load through `hooks/useApiData.js` (`useApiData(key, load)`: reloads when `key` changes, toasts errors). The assistant's answer streams over Reverb: `lib/echo.js` (`getEcho()`, private channel `ia-chats.{id}`, auth via `fetcher` to `/broadcasting/auth`); env `NEXT_PUBLIC_REVERB_*`.
- `contexts/ThemeContext.jsx` — `ThemeProvider` (generates the palette from the seed — cached, and the `THEMES` palettes are precomputed while idle —, writes it inline on `<html>` in a layout effect, persists it — seed, mode, variant and both computed palettes `{ light, dark }` for the inline script —, and on mount calls `applyStoredTheme` in a layout effect (in dev Strict Mode's remount clears what the script put on `<html>`); `setColorSeedHex`/`setMode` change the theme inside a `document.startViewTransition` crossfade of 200ms, or at once without support or with reduced motion) and `useTheme()`, plus the `THEMES` list.
- `contexts/ToastContext.jsx` — `ToastProvider` (renders the `Toast` list, max 4) and `useToast()` → `{ info, success, warning, danger, showToast, closeToast, closeAll }`. Mott imports `useToast`/`useTheme` from them; `contexts/` (auth, theme, toast) is the one exception to "Mott never imports from the root folders".
- `mott/theme/` — `palette.js` (`ROLES` maps M3 role → token name), `roles.js` (`FAMILIES`, `controlTint`, `selectionTint`), `themeScript.js` (no `'use client'`: the theme's localStorage keys `STORAGE_SEED`/`STORAGE_MODE`/`STORAGE_VARIANT`/`STORAGE_PALETTES`, `applyStoredTheme(modeKey, palettesKey)` and `THEME_SCRIPT`, that function as text for the inline script in `app/layout.js`).
- `mott/animations/` — the non-hook animation modules and components: `motion.js` (durations, eases, `MODAL_EASE` — easeOutQuint 350ms, the open/close curve of every modal —, `springEase`/`SPRING` for the content drop of `useContentSwap`, press/morph helpers), `reducedMotion.js`, `modalAnimation.js` (morph/anchored/reveal/fade modal animations; the close mirrors the open curve toward the trigger with the same duration), `scrim.js` (the veil of every modal and its compensation when they stack), `curtain.js` (top-to-bottom feathered mask reveal for modal content), `LoadingFlash.js` (a band of light rises bottom to top through its container while `active`; the parent needs `relative overflow-hidden`; props `color`/`strength`/`band`/`duration`/`pause`; only the component, its passes live in `useLoadingFlash`). Their hooks live in `mott/hooks/animations/`.
- `mott/hooks/` — `useAsyncAction` (runs an async fn, exposes `loading`/`error` from the thrown `Error.message`), `useModalLayer` (the global stack of open modals and their veils: `{ depth, enter, leave, setOverlay, overlayBelow }`, + `useModalLayer.md`). `mott/hooks/animations/` holds the animation hooks: `useEnterExit.js` (one reversible enter/exit timeline), `useSelectionMorph.js` (selection shape of a row of buttons), `useSelectionPill.js` (per-item selection background that grows from the center, used by the SettingsModal nav), `useContentSwap.js` (the curtain swap of content inside a modal — SettingsModal sections and password step, AuthModal screens, OnboardingModal steps: returns `{ ref, shownKey }`, `shownKey` lags `key` while the old content is hidden, the container's height tweens; `animate: false` follows `key` at once), `useLoadingFlash.js` (the Web Animations passes of `LoadingFlash`: one after another with `pause` between, never cut mid pass — when `active` turns false the running one ends —, with reduced motion it only pulses at the bottom; returns the band's ref).
- `mott/utils/` — `cn.js` (tailwind-merge extended with the named tokens), `maskEmail.js`, `fetcher.js` (fetch to `NEXT_PUBLIC_API_URL` with Sanctum cookies + `X-XSRF-TOKEN`, object `body` sent as JSON with `Content-Type: application/json`, retries once after a 419), `scrollLock.js`.

## Conventions

- Component files PascalCase (`Button.js`); private helpers camelCase next to them. Imports only through aliases (jsconfig): `@mott/*` → `./mott/*` for the design system, `@/*` → `./*` for everything else (`@/app/...`, `@/components/...`); no relative imports, no barrel files.
- `'use client'` only on components using state, effects, refs, context, event handlers or browser APIs. `Icon`, `GoogleIcon`, `Text` and non-component modules don't carry it. Browser globals only inside effects/handlers or behind `typeof document !== 'undefined'` (client components are still prerendered on the server).
- Async handlers are props — except AuthModal, SettingsModal and LogoutModal, whose API calls live in their hooks (SettingsModal only takes `open`, `onClose`, `triggerRef`); AuthModal's live in its screen hooks (it only takes `open`, `onClose`, `triggerRef`, `screen`, `email`, `token`, `verification`); a thrown `Error`'s message is shown by the component. The user comes from `useAuth()`.
- A modal's logic lives in its own hook (session from `useAuth()`, navigation with `useRouter()` inside the hook): don't add props so the opener decides it; props stay `open`, `onClose`, `triggerRef` and data that really comes from outside (a link's params).
- Write values directly where they are used (`fetcher('/api/me')`): no constants, intermediate variables or wrapper functions just to name or share a value, even if it repeats. Routes the developer configures come from `.env` and are read as `process.env.NEXT_PUBLIC_ROOT_PATH` / `NEXT_PUBLIC_REDIRECT_PATH` / `NEXT_PUBLIC_GOOGLE_AUTH_URL` right where they are used (literally: Next only inlines that form).
- Always merge classes with `cn` from `@mott/utils/cn`, never `tailwind-merge` directly (it would not merge `p-card` with `p-0`).
- Never build Tailwind class names dynamically (`` `type-${x}` ``): Tailwind only generates classes it finds literally in the source.
- Comments: short, one line, only where the why is not obvious.
- Hooks and stateful components are ordered: state and refs first (no header), then `// Efectos`, then `// Handlers`, then the return — see `mott/services/modals/useSettingsModal.jsx`.

## Design tokens (`app/globals.css`)

- Naming rule: `type-*` = typography classes (15 M3 roles `type-{display,headline,title,body,label}-{lg,md,sm}` plus `.type-emphasis`) · `mott-*` = internal component mechanics (`mott-morph`, `mott-state-layer`, `mott-btn`, `mott-field`, `mott-dialog`, `mott-trim`…). A component's long class strings live there as one utility for that use (`mott-nav-item`/`mott-nav-fab`/`mott-nav-icon`, `mott-settings-panel`/`-nav`/`-tab`, `mott-auth-panel`, `mott-menu-row`, `mott-text-link`, `mott-fullscreen-panel`, `mott-swatch`), not as style variables in the component; selected states come from ARIA attributes (`aria-current`, `aria-pressed`, `aria-selected`). The base Modal panel is `.mott-panel` in `@layer components`, so any utility passed through `className` overrides it · everything else is a Tailwind class generated from `@theme static` tokens: colors `--color-*` (`bg-surface-high`, `text-text-muted`, `bg-primary-soft` — M3 renamed: `container` → `-soft`, `error` → `danger`, `on-surface` → `text`, `surface-container-*` → `surface-{low,mid,high,highest}`), spacing `--spacing-{tight,group,section,block,card,page}` plus the responsive `gutter`/`layout` (redefined per breakpoint in the `:root { @variant md/lg }` block right after `@theme static`), breakpoints `--breakpoint-{sm,md,lg,xl,2xl}` (Tailwind's defaults made explicit; code is mobile first), widths `--container-{content,reading}` (`max-w-content`, `max-w-reading`), radii `rounded-{sm,lg,xl}` (`rounded-full` is Tailwind's own), `shadow-floating`, eases `ease-emphasized`/`ease-emphasized-decelerate`. The `type-*` values are written inside each utility, not as variables. Plain `var()` tokens in `:root` (`--icon-*`, `--control-size-*`, `--duration-*`, `--z-*`). Tailwind's default color palette is reset (`--color-*: initial`).
- The block between the `generated` markers is written by `npm run theme` (light inside `@theme static`, dark in `[data-theme="dark"]` + the `prefers-color-scheme` media query guarded by `:root:not([data-theme="light"])`) — never edit it by hand. At runtime `ThemeProvider` overrides the colors inline on `<html>`.
- Do not add `@import url(...)` for web fonts in `globals.css`: Next's CSS pipeline drops it — use `next/font` in the layout.
